# 通量世界设计蓝图 v3

> 2026-10-09。FluxLite 0.6.1、FluxDepths 0.3.0、FluxEcho 0.7.2 合并为一个模组 **FluxEcho** 之后的总体方案。
> 数字（耗电、半径、研究消耗）都是草案，做的时候再定，并且都放进配置。

## 〇、已定下的原则

1. **一个模组**：FluxLite 和 FluxDepths 并进 FluxEcho（0.8.0 已完成）。旧存档里的方块、物品、机器原样能用，不丢东西。
2. **贯穿整个 GTNH**：从蒸汽时代到 UHV 以后，每个阶段都有新的多方块、新功能、新材料。
3. **没有低级机器**：
   - 一种功能只有一座多方块，从头用到尾；
   - 靠相位核、覆层、研究去迭代升级它；
   - 不照 GT 那样每个电压等级重做一台、换一层外壳。
4. **新材料驱动进度**：
   - 解锁新内容要做新材料；
   - 做新材料要用前面的设备；
   - 新材料再变成覆层、模块、外挂件装回结构上，结构的样子也跟着变。
5. **成型即变形**：多方块搭好的那一刻，方块结构变成非标准的样子：悬浮、弧形、发光、会动。
6. **固定槽位**：模块搭在通量中枢规定的位置上，最终合成一座完整的建筑。中枢可以扩展，有空中的槽位。
7. **没有敌人**：不加任何威胁和事件，保持懒人取向。
8. **统一体系**：世界观、合成界面、全息影像、能源、机器界面、动画与美术，全部一套。
9. **单方块机器保留**：现有的单方块回响机器、采集器、连接器照样能单独用，给不玩整个流程、只想偷懒的人。多方块是给走完整流程的人的另一条路。
10. **环形扩展**：中枢外面是一圈圈的环：内环、外环，后期东西多了再开第三环。空中也有一层。
11. **模块要大**：模块是一座真正的建筑，不是一台大机器，整座城做成大建筑。模块还有**内部空间**：透过光门就能看到里面，走进去没有任何加载，里面是一个大空间，可以玩对应的内容（比如在魔力泉阵里面搭植物魔法）。
12. **发电**：可以发电，但每座发电模块只在两三个阶段里是顶尖的，不能超出所在阶段太多。
13. **通量碎屑只从碎片采集器出。**

## 一、世界观

### 1. 通量层的五层

| 层 | 是什么 | 在模组里 |
|---|---|---|
| **表层·能量之海** | 现实之下、贯穿所有世界的能量之海。在方块旁边开一个针孔，就能把电推进去、取出来。 | 通量连接器、控制中心、终端（原 FluxLite） |
| **记忆层·回响** | 流过通量层的一切，它都记得。亲手做过一次的事，在这里留下回响。 | 回响机器、回响图鉴 |
| **深层·碎片** | 世界诞生时留下的碎片。每条矿脉、每片地下流体，都是深层里一块碎片的投影。 | 碎片采集器、流体回响泵（原 FluxDepths） |
| **显化层** | 被钉住的通量层不再只是能量和记忆，它开始变成物质、变成结构。 | 通量中枢、通量材料、覆层 |
| **源点** | 通量层自己的形状，一切回响的源头。 | 最终阶段 |

### 2. 回响的规则

- **只有真实发生过的事才有回响**：真蜂、真要素、亲手做出的宝珠、亲手杀过的怪、世界生成时真实存在的矿脉。机器只认真东西，所以不会跳过进度。
- **回响很微弱**：要用电去放大它，所以每台机器都耗电。
- **回响认人**：回响属于留下它的团队，就是回响图鉴里的账本。
- **末影珍珠是通往通量层的那一环**：每台通量机器里都有一颗。

### 3. 五个时代

玩家在 GTNH 里一路往前走，也就一层层往通量层的深处走：

1. **针孔时代**（蒸汽–LV）：第一次在现实上开针孔。连接器把电和蒸汽送进能量之海；采集器借深层的碎片投出矿石。
2. **回响时代**（LV–MV）：发现通量层会记住做过的事。回响机器替你重复：养蜂、作物、刷怪、神秘、血魔法、植物魔法。
3. **锚定时代**（HV–EV）：团队留下的回响多到让通量层变得稠密。**通量中枢**钉进这片稠密处，把一小块通量层固定在现实里。从此开始有了算力和研究，有了第一批通量材料。
4. **显化时代**（IV–ZPM）：
   - 被钉住的通量层开始变成物质：显化物质、反重力晶格；
   - 建筑长出模块、升到空中，覆层一层层长在结构上；
   - 最后整座建筑完全显化，即**回响之城**。
5. **源点时代**（UV–UHV 以后）：中枢往下扎得足够深，碰到了源点。源点物质让建筑最后一次蜕变，也打开了终局的内容。

### 4. 设计语言

- **颜色**：
  - 深蓝黑底 `#0A1622`；
  - 青色是能量 `#4FE3FF`，紫色是回响 `#8A5CFF`，金色是样本 `#FFD27A`；
  - 显化物质是会变形的黑金，源点是星空；
  - 每个模块有自己的强调色。
- **形状**：环、弧、悬浮、六边形网格、细支架、晶簇。不用整块立方体堆墙。
- **动效语言**：
  - 涟漪：回响扩散；
  - 扫描：拓印；
  - 光弦：连接与轨迹；
  - 粒子流：能量和物质的输送；
  - 展开与折叠：进化和升级；
  - 生长：覆层从结构上长出来。
- **原则**：
  - 搭的时候，方块只是脚手架。
  - 成型那一刻，光从下往上扫过，实体方块溶解成悬浮部件。
  - 会动的都是渲染出来的。
  - 全部按光影安全的方式画，配置里都能关掉或降级。

### 3.3 通量中枢与环

**布局**：以中枢为圆心，一圈一圈往外扩。每一圈是一个**环**，环上是固定的槽位，模块就搭在槽位上。

```

                 ○ ─ ─ ○ ─ ─ ○ ─ ─  外环（半径 ~72，12 槽，LuV 起） ─ ─ ○ ─ ─ ○
                 │                                                          │
                 ○        ◇───◇───◇   内环（半径 ~32，8 槽，HV 起）          ○
                 │        │         │                                       │
                 ○        ◇  [中枢] ◇      ◇ = 内环槽   ○ = 外环槽          ○
                 │        │         │                                       │
                 ○        ◇───◇───◇                                         ○
                 │                                                          │
                 ○ ─ ─ ○ ─ ─ ○ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ○ ─ ─ ○

   空中：天顶（中枢正上方，穹顶）  天环（+40 格，半径 ~32，4→8 个悬空槽）  轨道（+96 格，卫星）
   地下：根位（中枢正下方，深根）
   内境：各模块的内部空间和城中城在同一维度的折叠区里，从光门进（见 3.10）
```

- **中枢本体**：11×11 的底座，往上一段段长。每进一个相位，就在顶上多搭一段悬浮环段。中枢自己就是可扩展的，相位越高，建筑越高。
- **内环**：半径约 32 格，8 个槽，每个槽能放 21×21 以内的模块。HV 2 槽、EV 4 槽、IV 8 槽。
- **外环**：半径约 72 格，12 个槽，每个槽能放 31×31 以内的大型模块（算力、大型仓储、内部空间大的模块）。IV 4 槽、LuV 8 槽、ZPM 12 槽。
- **第三环**：半径约 120 格，16 个槽，每个槽 41×41 以内，源点时代的巨型模块。UHV 8 槽、UEV 16 槽，也给以后加的东西留位置。
- **空中**：
  - **天顶**：中枢正上方，放回响穹顶。相位 II 起搭在中枢顶上的支架上，相位 IV 后脱离支架悬浮起来。
  - **天环**：中枢上空 40 格的一圈悬空槽，相位 IV 开 4 个、相位 V 开 8 个。要用反重力晶格做的浮空地基，光柱垂到地面。
  - **轨道**：中枢顶上的轨道锚放上卫星，卫星在更高处沿圆轨道绕中枢转。
- **地下**：根位。这里是一口通往通量层的井，同一座多方块一路进化：潮汐井（EV）→ 深根（LuV）→ 地脉核（UV），见 3.9。
- **模块是独立的多方块**，有自己的控制器。搭在槽位上，中枢就自动认出它，不用链接工具。中枢放好后，空槽位会投影出轮廓，告诉你搭在哪里、搭成什么样。
- **环廊和光桥**（自动生成，都是渲染出来的）：
  - 中枢到内环、内环到外环，沿八个方向各有一道放射状的导能光桥；
  - 同一个环上相邻的两个槽都有模块时，之间连成弧形环廊，整环搭满就合拢成一整圈；
  - 天环和地面之间是光柱。
- **成型的变化**：
  - 每个模块搭好最后一块，光扫过，脚手架溶解；
  - 换成这个模块自己的样子：生态穹的玻璃穹和花园岛、秘法庭的墨环尖塔、书库无限延伸的书格……
  - 拆掉任意一块，反向坍缩回脚手架。
- **占地**：第三环全开后直径约 280 格，做的就是大建筑；配置里可以整体缩放（`nexus.scale`）。地面上全是建筑；内部空间在同一维度远处的折叠区里（见 3.10），不占地面，也不动地下。
- **远景**：客户端的视距一般是 8–12 个区块，站在城的一边看不全另一边。中枢的光柱、各环、穹顶这些标志性的部分由我们自己的渲染器按简化模型画，远处也看得到。

**完全体：回响之城**

- 中央是五段悬浮环组成的光柱。
- 内环八座模块被一整圈环廊连成一体，外环十二座大型模块在更外一圈，放射状的光桥从中枢一路连到外环。
- 半空中天环的悬空模块围成一圈，光柱垂到地面。
- 天顶悬着穹顶发生器，半透明的六边形穹顶罩住整座城。
- 卫星沿轨道绕着中枢转。
- 各处覆层的晶簇、记忆丝网、显化外壳随运转节奏明暗起伏；满潮时，整座城的光一起变亮。
- 夜里光环亮起，极光垂下来。
- 进入源点时代后，外壳换成星空质感，第三环亮起，中枢上空打开一扇源点之窗。

### 3.4 升级：不换外壳，换"长出来的东西"

每座多方块有三条升级的路，没有一条是"拆了换高级外壳"：

1. **相位核**：
   - 控制器里的一个槽，代替 GT 的电压等级电路；
   - 相位核 I–V 由通量材料做，等级越高，电压上限、并行、速度越高；
   - 一座模块从相位核 I 用到 V，就从 HV 用到 ZPM。
2. **覆层**：
   - 结构上有若干**覆层锚点**，在锚点上装覆层方块；
   - 每种覆层给一种加成，也让结构的样子变化；
   - 锚点数量有限，要取舍：堆速度，还是堆能效，还是堆并行。

   | 覆层 | 材料 | 加成 | 样子 |
   |---|---|---|---|
   | 晶簇覆层 | 通量结晶 | 速度 | 青色晶簇从支架上长出来 |
   | 相位板 | 相位合金 | 能效 | 深蓝装甲板滑入、扣合 |
   | 共鸣窗 | 共鸣玻璃 | 范围、稳定 | 透明面板，随运转泛起涟漪 |
   | 记忆丝网 | 记忆丝 | 并行 | 光丝织成的网罩住结构，流光沿丝走 |
   | 显化外壳 | 显化物质 | 大幅全面加成 | 结构表面变成流动的黑金液态外壳 |
   | 源点辉光 | 源点物质 | 终局加成 | 星空质感，表面有星点闪烁 |

3. **研究**：在研究星图里点亮的节点，给某个模块解锁新功能或新数值。比如穹顶的防雷、书库的跨维度共享、生态穹的蝴蝶并行。

另外还有**外挂件**：小件装在模块的接口上，比如冷却环、增幅线圈、观测镜，作用小，样子显眼。

### 3.5 通量算力与研究星图

- **算力**：通量自己的计算资源，与 TecTech 无关。
  - 产出：中枢本体有一点基础算力；智子阵列是主要来源；记忆丝网覆层也能加。
  - 消耗：研究项目；书库的检索、全息沙盘、卫星这类模块也要持续消耗一点。
- **研究**：
  - 在中枢的研究星图里选一个节点，消耗"算力 × 时间"加上若干材料，有的节点还要图鉴里有某类回响记录；
  - 完成后解锁：模块的蓝图（控制器配方）、覆层种类、相位核等级、材料配方、模块的新功能、外观变化；
  - 研究属于团队，和图鉴一起存。
- **六个分支**（星图上的六个星座）：

  | 分支 | 解锁 |
  |---|---|
  | 构架 | 新槽位、空中平台、轨道、覆层种类、相位进化 |
  | 回响 | 生产模块、并行、书库共享 |
  | 能量 | 通量网络的升级、深根蓄能、能效 |
  | 深层 | 采集器并入中枢、深层钻井、流体回响、通往源点 |
  | 守护 | 穹顶的各项功能、水滴机库、天穹气象站 |
  | 算力 | 智子阵列、研究速度、算力上限 |

- **星图界面**：
  - 节点是星，分支是星座，已点亮的连线有光流过；
  - 研究进行中，数据流从中枢涌向那颗星；
  - 点开节点能看到消耗、解锁内容和一段设定文字；
  - 中枢附近，这张星图也会作为全息浮现在中枢上空。

### 3.8 回响穹顶

- **位置**：天顶位。相位 II 起搭在中枢顶上的支架上；相位 IV 后脱离支架，浮在中枢上空。
- **半径**：随相位 48 / 72 / 96 / 128 / 160 格（最后一级罩住三环全开的整座城），共鸣窗覆层还能再加。
- **功能**：每项单独开关、单独耗电，靠研究点亮。
  1. 范围内不刷敌对生物；
  2. 已在里面或走进来的敌对生物被推出去；
  3. 爆炸不破坏方块、不伤玩家：苦力怕、TNT、GT 机器爆炸都算；
  4. 拦截射进来的箭、火球等弹射物；
  5. 防雷击：闪电被引到穹顶顶点；
  6. 防火势蔓延；
  7. 挡雨雪，让 GT 机器不再淋雨着火。**需要先验证可行性。**
- **护盾值**：每次拦截消耗护盾值，耗尽后短暂失效，再从电网回充。
- **动效**：
  - 平时几乎透明，只有底边一圈微光；
  - 被击中时，六边形网格从受击点一圈圈亮起；
  - 下雨时，雨滴落在穹顶上溅起细小的涟漪；
  - 开机时从顶点向下展开，关机时收拢。
- **界面**：半径、各项功能的开关、护盾值、拦截记录（最近拦下了什么、在哪里）。

### 3.9 发电

规则：
- 每座发电只在两三个阶段里是顶尖的。
- 刚解锁时略强于这个阶段 GT 最好的常规发电（多 20%–50%），靠相位核和覆层升到后面一两个阶段。
- 再往后跟不上了，就该换下一座。
- 不白给电：每座都烧通量材料，产量还跟回响潮汐走（见 3.11），满潮多、枯潮少。

| 发电 | 位置 | 顶尖的阶段 | 烧什么 | 设定 | 样子 |
|---|---|---|---|---|---|
| **潮汐井** | 根位 | EV、IV、LuV | 通量结晶 | 通量层的潮汐涌上井口，推着井里的环转 | 一口发光的井，井口三层环随潮起落 |
| **天光帆阵** | 天环 | LuV、ZPM、UV | 共鸣玻璃帆（会磨损）、显化物质 | 光帆收下从通量层折射上来的天光，白天和高处更多 | 悬空展开的巨大光帆，随风翻动 |
| **地脉核** | 根位（潮汐井进化而来） | UV、UHV、UEV | 源点物质 | 深根接上地脉，深层的碎片在核里熔成能量 | 地下光脉汇入一颗悬浮的熔核 |
| **源点之心** | 第三环 | UEV、UIV、UMV | 源点残响 | 直接从源点取能 | 星空中的一颗心跳 |

相邻两座在交接的阶段重叠（LuV、UV、UEV），换代时不会断电。根位是同一座多方块的进化：潮汐井不拆，研究加材料让它长成深根，再长成地脉核。

具体数字（每阶段 EU/t、燃料消耗）在做的时候对照 GTNH 2.8.4 各阶段的主流发电（大型燃气涡轮、XL 涡轮、大型硅岩反应堆等）来定，放进配置。

### 3.10 内部空间：折叠区、内室与光门

**结论（2026-10-09，0.8.2 起）**：
- 内室放在**门所在维度**的折叠区里：每个维度最远的一角（x 和 z 都超过 1048576），那里什么都不生成；
- 门两边是同一个世界，**两边一直加载**，走近就能看到门里，穿门只是在同一个世界里挪个位置，不换世界、不重新加载；
- 内室是照着模块样子的**封闭房间**，壳体拆不掉。

0.8.1 的原型把内室放在一个专用维度里，结果是：每次进出都要换整个客户端世界（重新加载、强制垃圾回收）；门里的内容是服务器另发的一份方块镜像，没有方块实体，GT 机器在门里看不到。0.8.2 换成下面的做法。

**折叠区**

- 每个维度都有：x 和 z 都超过 1048576 的那一角。
  - 那里没生成过的区块直接生成成空的、算作已装饰：没有地形、矿、树，也不跑任何模组的世界生成；
  - 不刷怪；
  - 实现是一个 mixin，在 `ChunkProviderServer.originalLoadChunk` 开头接管折叠区里还没生成过的区块，别处完全不变。Angelica 和 ArchaicFix 都改了同一个方法里调用生成器的那一行，所以不在那一行上做文章，免得冲突。
- 内室一间隔 1024 格，排成 64 列的网格，在服务器最远视距（15 个区块）下也互相看不到。
- 内室在门所在的维度里：
  - 主世界的门通往主世界的折叠区，下界的门通往下界的折叠区；
  - 内室的群系和外面的门所在的地方一样。

**两边一直加载**

- 1.7.10 的客户端同一时间只拿着一个世界，服务器也只给玩家发他身边那一方块区块。所以两边一直加载的前提，是两边在同一个世界里；在这个基础上，再让服务器多发两边的区块：
  - 站在门前（`viewRange` + 16 格内）：门另一边要显示的区块（整间内室，或者内室门对面的外面那一片）一直发给你，之后那边的每个变化也照常发；
  - 在内室里：整间内室，加上外面的门周围一片（和服务器视距一样大），一直替你留着，那里的机器照常运转。
- 实现：
  - 玩家多看着这些区块，和看着身边的区块一样：服务器发区块、发方块变化、发方块实体的更新，GT 机器的状态包也照常发（GT 按"玩家是不是看着这个区块"决定发不发）；
  - 两个 mixin：玩家走开时这些区块不被收回；服务器整理发送队列时不把它们挤掉；
  - 玩家离开这个世界（下线、换维度、死亡重生）时一起放掉。
- 穿门时，服务器先把玩家挪过去，在服务器还没注意到他挪动之前，就按落脚的地方算好要留的区块。所以他原来有的区块一块都不会被收回：走进去时外面的留着，走出来时内室留着。单元测试检查了四个朝向下走进、走出都没有区块要重新发。

**透视：门里画的是世界本身**

- 门另一边就在客户端自己的世界里，所以门里画的是真实的方块和方块实体：
  - GT 机器的面和运转状态、箱子、魔力池都对；
  - 带特殊渲染的方块（TESR）每帧照常画；
  - 那边一有方块变化，就重建对应的那一块。
- 画法和 0.8.1 一样：
  1. 按门的位置和朝向，把另一边画进一张离屏画面，用的是和玩家一样的镜头，在光膜处切开；
  2. 光膜上每一点贴上它在屏幕上盖住的那个像素，就成了一个洞。
- **Angelica**：只适配 GTNH 2.8.4 自带的 1.0.0-beta66b。离屏画面只用它的 GL 状态管理器跟踪得到的调用：显示列表用正数 ID（走真实的 GL 显示列表），矩阵和属性栈照常压栈出栈，着色器程序先存后还。Angelica 自己的区块渲染和光影管线完全不碰。
- 上面是 0.8.2 的画法，0.8.3 起只在没有 Angelica、开着光影包或关了 `gates.realView` 时用。

**真正接通（2026-10-09，0.8.3 起）**

0.8.2 试玩下来：进门后还是有一下"加载"，门里看不到生物，外面的全息也看不到。原因是 Angelica 只给它画过的地方建区块网格，自己另画的门里画面不算；服务器也只给你发身边的生物和全息。0.8.3 换成：

- **用游戏自己的渲染器画门里**：每帧在画世界之前，把镜头换到门另一边"眼睛所在的位置"（一个不在世界里的摄像机实体），把整个世界再画一遍到离屏画面，再贴到光膜上。
  - 这样 Angelica 画门里时就顺手把那边的区块网格建好了：走进去时什么都不用等。
  - 方块、方块实体、生物、玩家、粒子、天空天气、各模组在"画完世界后"画的东西（全息投影）都自然在里面。
  - 只画光膜盖住的那块屏幕（剪裁框），视锥只留穿过光膜能看到的部分，最多两扇门。
  - 摄像机和门之间挡着的东西（内室门背后的墙）用斜近裁剪面切掉：把投影矩阵的近平面放到另一边的光膜上，OpenGL 和 Angelica 的区块着色器用同一个矩阵，画面在屏幕上不动，只改深度。
  - 摄像机常常站在墙外或石头里，Angelica 的遮挡剔除会把门那边全藏掉，所以画门里时关掉它（视锥已经很窄）。
  - 摄像机和玩家的镜头完全一致：走路的晃动、受伤的抖动、视野（包括 Angelica 的缩放）都照搬；它所在的"介质"按玩家眼睛所在的算，不会因为摄像机正好在湖里就变成水下的雾。
  - 门不在视野里但就在旁边时，也把那边的网格建好：0.8.3 是偶尔用一个像素的剪裁框画一次，0.8.5 起改成只让 Angelica 建网格、什么都不画。
  - 离门 16 格以内时，每隔几帧从门后四面八方建一次（0.8.3、0.8.4 只在外面的门前做几次，0.8.5 起里外都一直做），进了内室转身也都建好了。
- **服务器按"隔着门的位置"算距离**：玩家附近每扇连通的门，都给他一个"出了另一扇门后所在的位置"。实体跟踪、机器全息、魔力和鲜血的轨迹都按离他最近的那个位置算，门那边的生物和玩家、全息都会发给他。

**开着光影包时（0.8.4 起）**

0.8.3 试玩：用户开着 Complementary，结果整个退回了 0.8.2 的做法（0.8.3 把光影包当作限制）。光影包下不能在一帧里画两遍世界：它的阴影、合成和时间累积（TAA 之类）都假定一帧只有一个镜头。所以：

- 门里仍用简单画法（FarView），但补上另一边的生物、玩家、掉落物，以及 FluxEcho 自己"画完世界后"画的全息和动效（`client.FarDraw`：这些部件登记一次，画门里时把 `RenderManager` 的镜头临时放到门另一边再调一遍）。
- 区块网格照样提前建：直接调 Angelica 的 `SodiumWorldRenderer.updateChunks`，镜头是门另一边的摄像机，视锥是穿过光膜的部分，不画任何东西。每隔一帧一次。光影的阴影阶段有自己那份可见列表，不受影响。
- 穿门和不开光影包时一样：眼睛一过光膜就把主镜头换到另一边，经过光影照常画。
- 站在外面的门前时，内室那扇门的 FarView 也一起建，进去转身不用等。

**进门那一下不再重新加载（0.8.5 起）**

0.8.4 试玩：进出已经无感，但走进去的一瞬间内室的建筑还会重新加载一次。原因是 Angelica（Sodium）只给"四周邻居区块都在"的区块建网格。服务器只发了门里显示的那片区块，最外一圈缺邻居，网格就一直建不出来，要等走进去、身边的区块发过来才建。所以：
- 服务器给门那边要显示的每一片（整间内室、内室门对面的外面那片）外面**多留一圈区块**。单元测试逐个检查十种内室在四个朝向、里外两侧：门里显示的每个区块，八个邻居都已经发给客户端了。
- 离门 16 格以内时，从门后四面八方的预建一直重复做（Angelica 每次只建一部分，每帧还会清空待建队列，做几次不够）。

**穿门**

- 有 Angelica（0.8.3 起，0.8.4 起开光影包也一样）：
  - 眼睛一穿过光膜，客户端就把镜头换成另一边的摄像机来画世界，不等服务器；
  - 服务器把玩家挪过去时，客户端把他放到眼睛已经在的位置（离服务器给的位置不到 3 格且不卡墙时），速度、朝向、上一帧的位置都按门的转向带过去，所以下一帧和上一帧接得上；
  - 骑乘中、刚穿过门的 0.6 秒内，客户端也和服务器一样不算穿门。
- 简单画法：画面停在门里看到的样子，过一道很短的涟漪（约 0.25 秒）就淡出。
- 不换世界，客户端不重新加载，也没有强制的垃圾回收。

**内室**

- 封闭的房间，壳体是"内室壳体"（地面、墙、顶、柱子、灯、光带）和"内室玻璃"：
  - 挖不掉、炸不掉，凋灵和活塞也动不了；
  - 壳体和里面的空气只要碰到（连对角也算）就是壳，所以走、流、光都出不去，单元测试逐格检查。
- 有灯：地砖灯、顶灯、墙上的光带。单元测试按 Minecraft 的光照算法算过，每种内室地面上最暗的地方也有 8 级以上的光。
- 玻璃顶的内室有真天空：蜂看得见天，作物晒得到太阳。
- 门在南墙边，朝北对着房间。
- 形状照着 3.7 的模块来：

- 盖内室时，方块直接写进区块再统一打一次光。一间内室几万个方块，一个一个放会让光照重算几万次。

- 都在同一个维度里，在大厅和各个内室之间走是无缝的。

**光门（特色）**

- **样子**：
  - 悬浮的环段围成门框，中间是一层流动的光膜；
  - 看进去是另一边的空间，边缘有细细的色散和涟漪。
- **光影包**：不开光影包时，门里就是游戏自己画的世界。开着光影包时，门里用简单画法，不经过光影包，所以门里没有光影的阴影和泛光，也看不到别的模组画在世界上的东西和粒子；进出照样无缝。光膜本身照常按全息的光影安全写法画。
- **设置**：
  - `gates.viewRange`：多远能看到门里；
  - `gates.liveView`：关掉后光膜只发光；
  - `gates.realView`：关掉后回到 0.8.2 的简单画法和涟漪过渡；
  - `gates.holdBase`：在内室里时，外面是否一直留着。

**0.8.1 的旧地块**

- 第一次用 0.8.2 打开存档时，每扇旧光门在自己的维度里新开一间城中城大厅并改连过去。
- 旧地块里的东西留在 `DIM7270` 原地。
- `DIM7270` 保留注册，只为让旧存档能打开。

| 方案 | 透视 | 进出 | 结论 |
|---|---|---|---|
| **同一维度的折叠区 + 两边一直加载 + 游戏自己的渲染器再画一遍**（0.8.2，0.8.3 起接通） | 实时，整个世界（生物、粒子、全息都在）；开光影包时是简单画法 | 眼睛过光膜就换镜头，网格提前建好，无感 | **采用** |
| 专用内境维度 + 镜像透视 + 涟漪（0.8.1） | 只有方块，没有方块实体 | 换世界，重新加载 | 原型，已换掉 |
| 同一维度，挖空中枢下面的地下 | 实时 | 不重新加载 | 不采用：要挖地下 |
| 客户端同时拿两个世界（Immersive Portals 的做法） | 实时 | 零停顿 | 要重写网络、世界管理和渲染，渲染要钻进 Angelica 内部；不采用 |

### 3.11 回响潮汐与通量终端

**回响潮汐**
- 两层节奏：
  - **日潮**：每个游戏日一涨一落，午夜满潮、正午枯潮；
  - **月相**：决定这一天的潮有多大。满月大潮、新月小潮，8 个游戏日一轮（现实约 2 小时 40 分钟）。
- 幅度（默认值，都在配置里）：
  - 大潮（满月）：午夜 +20%，正午 −20%；
  - 小潮（新月）：±5%；其余月相按比例；
  - 一整天平均下来正好是 100%：挂机的总产量不变，会掐时间的人可以把耗时的批次放在满潮做。
- 影响的是速度：回响机器、模块、发电的工作速度跟着潮走，每次工作的耗电和材料不变。
  - 潮汐井是"吃潮"的发电，幅度加倍（大潮 ±40%）；
  - 研究星图里有"稳潮"：降低自己的中枢受潮汐的影响；
  - 不想要的话可以整个关掉（`tides.enabled`）。
- 满潮之夜（满月午夜前后两小时）：天上出现淡淡的极光，回响之城的光一起变亮。
- 潮汐表显示在通量终端和中枢的全息上。

**通量终端（全信息终端）**

原 FluxLite 的手持终端扩成什么都能看的终端，任何距离、任何维度都能用。

| 页 | 内容 |
|---|---|
| 网络 | 团队通量网络：输入输出、曲线、告警（原有的功能） |
| 机器 | 所有通量机器：单方块回响机器、采集器、中枢的各个模块的状态 |
| 图鉴 | 回响图鉴：团队做过什么 |
| 研究 | 研究星图：可以远程选择研究，用的是绑定的中枢的算力 |
| 中枢 | 中枢的相位、各环的模块、能源面板 |
| 潮汐 | 潮汐表和接下来的大潮 |
| 典籍 | 通量典籍：世界观和已解锁条目的设定 |

**解锁绑定在终端上**：
- 研究解锁的东西属于终端的主人，带着终端走到哪里都算数；
- 终端可以绑定到一座中枢，绑定后你的解锁和中枢共享：同一座中枢上绑定的所有人，解锁取并集，一起用；
- 没有中枢、只用单方块机器的人，终端照样能看网络、机器、图鉴、潮汐。

### 3.12 合并 FluxLite 和 FluxDepths（0.8.0 完成）

旧存档必须原样能用。查下来 Forge 有两条限制：`FMLMissingMappingsEvent` 只把**自己模组 ID 名下**的缺失注册名交给模组处理；强制加载区块的票据、`getSuggestedConfigurationFile()` 也都按模组 ID 走。所以没有走"改名成 `fluxecho:*` 再重映射"的路，而是：

| 东西 | 做法 |
|---|---|
| 代码 | `com.fluxlite`、`com.fluxdepths` 原样搬进 FluxEcho 的 jar，各自仍是一个 `@Mod`（`fluxlite`、`fluxdepths`），在 `mcmod.info` 里 `parent` 设为 `fluxecho`，模组列表里挂在 FluxEcho 下面 |
| 注册名、方块实体 ID、GT 机器 ID 24520–24529 | 全部不变，存档原样读 |
| 配置文件、网络通道、区块加载票据、Waila 注册 | 全部不变（`fluxlite.cfg`、`fluxdepths.cfg`） |
| 任务书 | 不用改，物品名本来就是 `fluxlite:*`、`fluxdepths:*` |
| 通量控制中心改名 | 只改显示名为「通量监控台」（Flux Monitor），注册名 `control_center` 不变 |
| 和旧模组同时装 | FML 发现同一个模组 ID 出现在两个 jar 里，会提示模组重复并停止加载，不会重复注册 |

发版说明里写清楚："先备份存档；删掉 FluxLite、FluxDepths 和旧的 FluxEcho，只留新的 FluxEcho"。

以后的统一工作（0.8.x）在这个基础上做：三者共用 `com.fluxecho` 的界面、全息、NEI 组件，旧包里的类逐步改用它们；注册名和模组 ID 不动。

FluxLite 和 FluxDepths 的仓库归档，README 指向 FluxEcho。

### 3.13 技术方案

- **多方块**：GT 的 `MTEExtendedPowerMultiBlockBase` 加 StructureLib。投影预览、自动搭建、NEI 结构预览都有。
  - 0.9.0 实际做法：中枢和模块是**自己的 TileEntity**（`nexus.TileMultiblock`），不是 GT 机器，不占 GT 机器 ID。电从团队无线电网直接取，不需要能源仓；StructureLib 照样用（`ISurvivalConstructable` 投影和自动搭建，`IMultiblockInfoContainer` 给 NEI 三维预览）。
  - 检查结构时记下 StructureLib 实际查过的每一格（`nexus.Recorded`），隐藏和可穿过的方块按这份记录来，所以和投影仪的朝向一定一致，不用自己算旋转。
  - NEI 预览世界里的方块实体（`realWorld()` 为假）不进中枢登记表、不改隐藏表。
- **通量构架系列方块**：
  - 构架支柱、弧形板、导能柱、悬浮环段、晶核座、浮空地基、模块地基、覆层锚点；
  - 都是不完整的方块，用 ISBRH 画进区块网格，对光影友好；
  - 带"已整合"状态，成型后部分方块隐去，换成渲染件。
- **渲染库**：
  - 程序生成的环、球壳、半球网格、光束、光弦、粒子流、全息面板、晶簇、液态金属外壳；
  - 都在 `RenderWorldLast` 里画，沿用现在全息的光影安全写法；
  - 按距离降级，远处简化，配置可关。
- **中枢调度**：
  - 模块控制器启动时找附近的中枢，确认自己在哪个槽位；
  - 中枢每隔 N tick 统一调度：分配算力、扣电、施加相位和覆层效果、推进研究。
- **环和槽位**：槽位按中枢的坐标和朝向算出固定位置；中枢扫描各槽位上的模块控制器，找到就认。环廊、光桥由中枢按已占用的槽位生成，只是渲染，不是方块。
- **内部空间**：折叠区、内室和光门，见 3.10。门的位移、折叠区布局、内室形状、两边要留的区块、穿门判定都是纯逻辑，写单元测试。
- **GT 机器 ID**：
  - FluxEcho 的 24530–24569 还剩 28 个；FluxDepths 的 24520–24529 并进来以后，一共是 24520–24569；
  - 中枢、十几个模块、空中和轨道件都在这个范围里；
  - 不够时在配置里另开一段。
- **性能**：
  - 大型渲染做视锥和距离裁剪；
  - 粒子数量有上限；
  - 服务端扫描限频；
  - 穹顶事件只看它所在的维度。
- **测试**：只靠单元测试和构建，不开游戏测：
  - 结构定义、槽位判定、相位条件、研究树、算力分配、覆层加成、穹顶判定、潮汐曲线、光门的几何都写成纯逻辑，放在 `logic`；
  - 画面（光门的透视、成型动画）单元测试测不到，要你在游戏里看，所以这类东西先做小原型；
  - 合并后三边的测试一起跑（0.8.0：180 个）。

## 六、已回答的问题（2026-10-09）

1. **名字**：核心叫通量中枢；原 FluxLite 的通量控制中心改名通量监控台。
2. **布局**：可扩展的环：内环、外环，后期第三环；空中有天顶、天环、轨道。
3. **单方块机器**：保留，给只想偷懒、不走整个流程的人用。
4. **发电**：要做。每座在两三个阶段里是顶尖的，不能超出所在阶段太多（见 3.9）。
5. **通量碎屑**：只从碎片采集器出。
6. **内部空间**：要做，模块要大，进出无感（见 3.10）。
7. **回响潮汐**：要做，加上全信息的通量终端，解锁绑定在终端上，可以绑定到中枢共享（见 3.11）。

8. **占地**：200 格无所谓，再大也可以，做的就是大建筑。环的半径放大到 32 / 72 / 120（见 3.3）。
9. **潮汐**：幅度和周期由我定：日潮加月相，大潮 ±20%、小潮 ±5%，一天平均 100%（见 3.11）。
10. **城中城**：可以做；**光门**是特色（见 3.10）。
11. **内境的位置**：不挖地下；里面强加载，走近门就显示门里的内容（见 3.10）。
12. **光门原型的反馈**（0.8.1）：进出会重新加载、门里看不到机器。两边都要一直加载；只适配 GTNH 2.8.4 的 Angelica（1.0.0-beta66b），可以深入适配；内室不要做成空岛，要照着对应多方块的样子做成封闭的房间，基础方块拆不掉。→ 0.8.2 按这些重做（见 3.10）。
13. **光门重做的反馈**（0.8.2）：穿门还是动画过渡，进内室还要加载内部的建筑。要两个世界提前加载、真正无感进出，门外的全息也要正常显示，要真正接通。→ 0.8.3 用游戏自己的渲染器画门里、无缝穿门、隔门发全息（见 3.10）。
14. **光影包**：你一直开着光影包（Complementary + Euphoria Patches）玩，画面效果都要在开着光影时成立，不能"光影下退回简单版本然后算作限制"。→ 0.8.4 开光影包也无缝。
15. **进门那一下**（0.8.4）：进出没问题了，但进入的一瞬间内部建筑还会重新加载一次。→ 0.8.5 门那边多留一圈区块、持续预建（见 3.10）。
